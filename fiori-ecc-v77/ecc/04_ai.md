# 4. AI in the Goals app

The AI only suggests. A person always chooses, and nothing the AI writes is saved unless someone clicks it.
Every call is logged, with what was asked, what came back, and what the person accepted.

## The model and the call

| | Canvas today (`developer/ai.mjs`) |
|---|---|
| Model | `qwen-flash`, the company's own model (the platform's `llm` resource). Goal text stays inside the company |
| Call | OpenAI-compatible `POST {base}/chat/completions`, `temperature 0.4`, `max_tokens 900`, 25-second timeout |
| System prompt | The goal-writing rules: the cascade, one sentence, starts with a verb, measurable with a number and a date, supports the goal above, 3 to 5 goals a person, plain English, never invent names, **answer with JSON only** |
| Limit | 40 calls a minute per person |
| Answer check | The JSON is parsed and cut to size on the server (`shape()`); a bad or empty answer counts as a failure and the page falls back |
| Endpoint for the page | `POST /api/ai` with `{task, context, employeeId}`; `POST /api/ai/<logId>/accept` with the text the person chose |

## The five jobs

| Job (`task`) | Where in the app | Input (`context`) | Output |
|---|---|---|---|
| `goals` | New goal wizard, step 2; after **Accept** on a contributor invitation ("Make this goal your own?") | `role`, `above` (goals of the person above, or the goal being contributed to), `mine` (their goals), `hint` | `{options:[{text, why}]}` up to 6 goal sentences |
| `measures` | New goal wizard, step 3 | `role`, `goal` | `{options:[{text, why}]}` 4 measures, each with a number, a start, a target and 31 December 2027 |
| `review` | AI review card on every goal page | `role`, `title`, `measure`, `due`, `parent`, `above`, `top` (true for the Director General) | `{ready, checks:[{ok, text, fix?:{field, value}}], better}`. The page shows at most **5 checks, problems first**; a `fix` becomes a one-click **Apply** |
| `comment` | Returning a goal (approver) | `title`, `measure`, `issues` | `{options:[{text}]}` 3 polite return comments |
| `translate` | The **English \| العربية** switch on the goal page and the goal popup | `text` (one field), `to` (`ar` or `en`) | `{text}` the translation. Shown under the original; **the goal itself is never changed** |

The exact prompts are in `developer/ai.mjs` (`RULES` and `TASKS`). Keep them word for word when moving: the page relies on the JSON shapes.

Rules the server enforces on answers (`shape()` in `ai.mjs`): a `review` fix for `due` must look like `31 December 2027`; a fix for `parent` must be one of the goals above, copied exactly; the Director General's review never asks for a goal above.

## Logging — `ZAJMN_AILOG` (Canvas: `ai_log`)

One row per call: who (`PERNR`), `TASK`, `MODEL`, `REQUEST` (the context, JSON), `RESPONSE` (the answer or the error, JSON),
`STATUS` (`ok` / `error`), `LATENCY_MS`, `TOKENS`, `ACCEPTED` (the text the person took, filled later), `ASKED_BY` (logon user), `CREATED_AT`.
Insert only, like `ZAJMN_LOG`. This is the evidence for the audit: what the AI proposed and what a person decided.

## Running it next to ECC — choose one

**B. ABAP calls the model (built; recommended).** The page sets `AJMN_CONFIG.aiOnEcc = true` and posts each request to the entity set **`AiRequests`**
(`Task`, `Pernr`, `Context` as JSON); `ZCL_ZAJMN_GOALS_DPC_EXT->AIREQUESTS_CREATE_ENTITY` calls **`ZCL_ZAJMN_AI=>ASK`**, which builds the same prompt as `ai.mjs`,
calls the model through SM59 destination **`ZAJMN_LLM`** (key and model in table `ZAJMN_AICONF`), applies the same checks as `shape()`, writes the `ZAJMN_AILOG` row
and returns `LogId` and `Answer` (the job's JSON). What the person takes is recorded by the function import **`AcceptAI`** (`LogId`, `Text`).
Same 40-a-minute limit and 25-second timeout as Canvas. Tested in the page against `developer/mock-gateway.mjs` (`MOCK_AI=1`); the ABAP itself is not compiled yet.

**A. Keep the company model behind Canvas.** `AJMN_CONFIG.aiUrl = "https://talent-suite--erp.canvas.ajnai.net/api"` (and no `aiOnEcc`). The page calls `aiUrl/ai` and
`aiUrl/ai/<id>/accept`; logs stay in Canvas's `ai_log`. Needs a same-site route from the launchpad to Canvas (BTP destination or reverse proxy — a direct
cross-site call is blocked by the browser and the Canvas sign-in), and a security decision that goal text may leave ECC.

**C. SAP BTP generative AI hub** later is possible with the same prompts and shapes.

## Before go-live

* Data protection: goals are personal data. Decide what may be sent to the model (option A sends goal text to Canvas). Mention the AI in the employee notice.
* Label AI text: the page marks suggestions as suggestions; nothing is saved without a click. Keep it that way.
* Keep the per-person limit and the timeout; show the goal library when the AI fails (the page already does).
